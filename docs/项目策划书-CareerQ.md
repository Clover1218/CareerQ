## 一、项目名字

**推荐主名称：CareerQ**

| 名称 | 含义 | 适合场景 |
|---|---|---|
| CareerQ | 学生的问题与 HR 的经验之间的一座桥，公开、异步、可沉淀 | **推荐主品牌** |
| 职答 | 职场人回答职业问题，简洁直接 | 产品名 / Web 站点名 |
| 职场回声 | HR 的观点被学生看见、点赞、回应，形成回声 | 内容社区感更强 |
| 前辈请回答 | 突出「HR / 职场前辈—学生」的问答关系 | 活动感强，适合冷启动 |
| 职途问答库 | 强调结构化、可检索、可沉淀 | 偏工具和资料库 |

- **Slogan**：让好问题遇见对的人，让经验公开沉淀。
- **定位一句话**：面向大学生与 HR 的公开、异步、结构化职业问答信息库，不做私聊社交。

## 二、项目概述

「CareerQ」是一个连接大学生与 HR / 职场人的职业发展问答平台。HR 目前选择回答学生提出的公开问题，并回复学生的公开追问；后续规划公开发表职业发展、招聘面试、行业选择等原创观点；学生可以提问、点赞、收藏、标记「有用」，但不与 HR 进行一对一私聊。

产品核心不是「社交」，而是「公开问答库」：所有互动发生在公开页面或指定话题下，内容可审核、可沉淀、可检索，从而降低 UGC 平台的监管与运营风险。

## 三、背景与问题

具备双边资源：一端是大量熟悉职业发展和企业人力资源管理的 HR，另一端是大量有职业困惑的学生。双方有交流意愿，但直接面对面或私聊存在平台监管、隐私、安全、内容不可控等问题。

因此需要把「直接对话」转化为「公开异步互动」：

1. 学生公开提问；
2. HR 选择回答；
3. 学生点赞、收藏、追问；
4. 优质内容被精选和沉淀；
5. 平台方对公开内容进行审核和干预。

## 四、产品定位

- **产品名**：CareerQ
- **产品形态**：公开、异步、结构化的职业问答信息库
- **产品载体**：响应式 Web 站点，兼容手机与桌面浏览器
- **核心用户**：大学生、HR / 职场答主、平台运营方
- **明确不做**：私信、好友、实时聊天、匿名树洞、招聘投递、简历交易、付费咨询

**核心价值**：

- 对学生：获得真实职场人的公开经验，降低信息差；
- 对 HR：低成本表达观点、建立个人专业形象、影响潜在人才；
- 对平台：形成可审核、可沉淀、可复用的职业发展内容库。

## 五、核心机制

- **学生端**：发布问题 → 选择标签 → 等待 HR 回答 → 点赞/收藏/标记有用 → 可对回答进行公开追问。
- **HR 端**：浏览开放问题 → 选择愿意回答的问题 → 发布回答；原创观点帖列入后续开发范围，话题征集另行评估。
- **平台端**：审核内容 → 精选问答 → 运营话题 → 处理举报 → 维护答主。

**关键原则**：所有问答围绕公开问题进行，异步、留痕、可审核；学生提问和追问，HR 回答及回复追问，运营只负责审核与处理举报。

## 六、功能规划

### MVP 阶段功能

1. **学生提问**：公开问题的标题、描述和标签（面试准备、简历、行业选择、实习、职业规划等）。
2. **HR 回答**：HR 浏览问题池，选择回答；回答支持「一句话建议」和「详细经验」两种长度。
3. **HR 原创观点帖（待开发）**：HR 主动发布短观点或经验分享，包含发布、我的帖子、审核状态、公开展示与互动；不等同于现有回答功能。
4. **互动信号**：点赞、收藏、「有用」标记；不做「踩」和公开负面评分。
5. **精选问答（待开发）**：运营根据互动和内容质量组织公开问答专题，需另行实现。
6. **举报与审核**：已有词库和规则初筛、人工审核与举报后端；独立运营页面待完善，大模型审核和封禁管理不计为已完成。
7. **账号与认证**：演示采用固定验证码与测试身份；真实短信验证、HR 在职/企业认证暂缓，学校和专业仍可选填。
8. **搜索与标签**：已有搜索词、标签、时间范围筛选，以及推荐、最新、热门排序。

### 当前交付状态

公开问答、学生提问与追问、HR 工作台三类列表、主问题回答和指定追问回复已可运行。HR 与学生使用独立工作入口。角色越权、审核状态、撤回/下架计数与分页边界仍按每轮任务逐项验收。学生消息面板仅为示例，浏览历史保存在本机。

HR 不能创建学生问题、发起学生追问或审核；运营不能以审核身份提问或回答。后续观点帖只扩展 HR 的原创公开内容发布，不改变上述问答权限。

### 后续功能

- HR 发起话题讨论，学生参与回应；
- 问答合集与专题页；
- 「HR 观点征集—学生回应—HR 再回应」的循环话题；
- 内容收藏夹与个人成长记录；
- 数据看板：问题回应率、回答时长、精选内容表现。

## 七、用户流程

**学生流程**
游客浏览公开问答 → 注册/登录 → 发布公开问题并选择标签 → 等待回答 → 点赞/收藏/追问 → 形成个人收藏。

**HR 流程**
登录 → HR 工作台浏览待回答问题或自己的回答记录 → 回答主问题/回复学生追问 → 查看审核与后续追问。原创观点帖实现后增加独立发帖入口。

**运营流程**
登录运营页面 → 审核可能违规的内容 → 查看上下文并通过/驳回/下架 → 处理举报并留痕。精选与专题为后续内容运营能力。

## 八、合规与审核设计

- **身份核验**：公开身份与后台认证分开，真实短信及 HR 认证在接入前不得对外声称完成；演示账号仅用于测试。
- **内容审核**：当前采用词库和内置规则初筛、人工复核；未来接入内容安全 API 或模型需单独验收。规则重点关注就业歧视、虚假招聘、人身攻击和隐私泄露。
- **数据最小必要**：只收集手机号和必要身份标识；公开页面 HR 可展示为「某互联网公司 HR」，不暴露真实姓名。
- **未成年人保护**：如涉及未满 18 岁学生，增加内容限制和监护人/学校相关合规提示。
- **免责声明**：明确平台为职业发展交流项目，不代表学校官方就业指导平台；回答为个人观点，不构成招聘承诺。
- **应急机制**：举报处理时限、违规内容下架、账号封禁、重大风险人工介入。

> 具体合规要求建议在上线前咨询法律或平台合规专业人士。

## 九、冷启动方案

**第一阶段：邀请制跑通闭环**

- 从认识的 HR 中邀请 10—15 位愿意分享、表达清晰的「首批答主」；
- 从学生中邀请 1—2 个学院或专业的学生；
- 由运营准备第一批选题，通过学生提交或明确标识的演示种子数据形成初始问题，不授予运营学生提问权限；
- 核心指标不是用户数，而是「学生问题能否在 24—48 小时内得到至少一个有效回答」。

**第二阶段：内容沉淀与开放注册**

- 形成 100 条以上真实问答后，开放学生注册；
- 用「本周精选」「热门标签」「HR 观点帖」做内容运营；
- 逐步扩大 HR 答主池，保持回答供给。

## 十、指标体系

**核心指标**

- 问题回应率：发布问题中获得至少 1 个 HR 回答的比例；
- 首次回应时长：目标 24—48 小时内；
- 有效回答率：被点赞/收藏/标记有用的回答比例；
- 次周留存：学生和 HR 的周活跃留存；
- 举报处理时长；
- 精选内容数量与收藏量。

**冷启动成功标准**

- 4 周内，80% 以上学生问题在 48 小时内获得至少 1 个 HR 回答；
- 8 周内，沉淀 100 条以上公开问答；
- 首批 HR 答主中，至少 60% 愿意持续参与；
- 无重大内容安全事故。

## 十一、路线图

| 阶段 | 时间 | 重点 |
|---|---|---|
| MVP 开发 | 第 1—4 周 | 提问、回答、观点帖、点赞收藏、审核后台 |
| 冷启动 | 第 5—8 周 | 邀请 10—15 位 HR、1—2 个学院学生，跑通回应闭环 |
| 内容沉淀 | 第 9—12 周 | 精选问答、标签体系、话题讨论、搜索优化 |
| 扩展 | 第 13 周起 | 扩大 HR 答主池、开放注册、形成专题内容库 |

## 十二、团队与资源

- **团队规模**：本项目由王、季、李 3 名成员共同开发。
- **分工原则**：采用三人按业务模块全栈开发，并进行交叉审查和共同联调。李负责 HR 与运营；公共和学生模块由对应负责人维护，共享文件变更先协调归属。

| 成员 | 主责方向 | 现阶段职责 |
|---|---|---|
| 王 | 公开浏览与公共展示（建议） | Feed、筛选、公开展示与相关接口协同，具体 owner 由团队确认 |
| 季 | 账号与学生提问（建议） | 登录、学生提问、我的问答和学生交互，具体 owner 由团队确认 |
| 李 | HR 与运营（已确认） | HR 工作台、回答与追问回复、后续原创观点帖、运营审核与举报的前端和后端 |

AI 工具仅作为辅助开发手段，不计入团队成员或人类审查人数。所有模块通过独立任务分支和 PR 交付；至少经另一位人类成员审查。当前工程为 Vue3 + TypeScript、Spring Boot 3 + Java 21 + MyBatis，生产 MySQL 8，本地 H2。

预算重点：开发工具、短信/邮件验证服务、审核人力、内容运营、合规咨询。初期不做多端，先完成兼容手机与桌面浏览器的轻量响应式 Web 站点。

## 十三、主要风险与应对

| 风险 | 应对 |
|---|---|
| HR 参与不足 | 首批邀请制，降低回答成本，设置「一句话建议」 |
| 学生提问质量低 | 提供提问模板和标签，运营筛选后发布 |
| 内容合规风险 | 公开异步、规则初筛 + 人工复核、禁用词库与举报机制 |
| 被误认为学校官方平台 | 明确个人发起项目定位，避免使用学校官方名义 |
| 变成招聘或私聊工具 | 产品层面不设私信、不设简历投递、不设付费咨询 |

## 十四、结论

「CareerQ」把「不让直接对话」从合规妥协升级为产品定义：不做社交，做公开、异步、结构化的职业问答库。先用手上 HR 和学生资源跑通「一个问题必有回应」的最小闭环，再逐步沉淀内容、扩大答主池。这个路径轻、可控、可审核，适合作为项目的起步形态。
