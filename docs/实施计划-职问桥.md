## 1. 当前基线

工程已采用 Vue3 + TypeScript 与 Spring Boot 3 + Java 21 + MyBatis。生产使用 MySQL 8，默认 dev 使用 H2 MySQL 兼容模式。公开问答和 HR 主流程已可运行，后续工作以当前 main 和实际接口为基线，不再按早期 M0 待启动计划推进。

| 模块 | 已具备 | 后续验收或开发 |
|---|---|---|
| 环境与后端骨架 | 多模块 Maven、统一响应、Flyway、健康检查、OpenAPI | 生产环境验证与部署复验 |
| 登录与资料 | 开发验证码、注册/登录/登出、会话、角色、资料与头像接口 | 真实短信、HR 认证、角色登录落点 |
| 公开问答 | 公开提问、Feed、详情、筛选、标签、互动、追问与撤销 | 状态与计数一致性、窄屏和异常情况验收 |
| HR 回答 | 独立工作台、三类列表、每页五条、主问题回答、指定追问回复 | 新追问/待回复提示、卡片与详情能力衔接 |
| 运营 | 审核、词库、举报处理和指标后端 | 独立审核与举报页面；HR 与运营入口权限联调 |
| HR 原创观点帖 | 第一阶段已实现：独立模型、服务器草稿、本人帖子管理、提交待审及撤回 | 第二阶段运营审核；第三阶段公开展示和互动 |
| 消息与历史 | 学生消息面板示例、本机浏览历史 | 真实通知和按账号隔离的历史记录 |

“已具备”表示代码已有相应能力，不等于全部边界验收完成。每次变更的测试结果以该次 PR 为准。

## 2. 三人交付边界

- 王：公开浏览、公共展示和相应接口协同；具体 owner 由团队确认。
- 季：账号、学生提问和学生页面；具体 owner 由团队确认。
- 李：HR 与运营模块全栈开发，包含工作台、回答、追问回复、后续观点帖、审核与举报。
- AI 协助实现、文档和验证，不代替人类 owner 或另一位人类成员审查。

学生能提问和追问；HR 只能作答及回复学生追问；运营只能审核与处理举报。HR 不能提问、发起学生追问或审核。共享文件与契约调整需要对应负责人协调，不能直接用一个模块的版本覆盖另一个模块。

## 3. 下一阶段顺序

### 阶段 A：范围清理与基线一致

- 清除停用业务的运行时代码、公开调用、演示数据与接口文档。
- 保留既有 Flyway 迁移的校验历史，后续数据结构变更使用新迁移。
- 对照最新主线整理代码与文档，区分已实现、占位和待开发能力。
- 验证公开浏览、学生提问、HR 回答及回复追问、运营审核与举报仍正常。

### 阶段 B：HR 现有流程收尾

- 核对回答撤销/下架后的计数、列表分类和公开可见性。
- 明确撤回与下架的状态文案，避免用户误解处理原因。
- 完善 HR 默认登录落点，以及卡片到指定追问回复的入口。
- 在“我回答过的”中增加新追问、待回复或更新时间提示；按真实数据验收。

### 阶段 C：运营审核页面

- 展示待审内容与必要问题上下文。
- 通过、驳回和下架有清楚的操作反馈，操作后刷新队列和内容状态。
- 举报列表、内容定位、处理结果与备注联调。
- 运营与 HR 互不能访问对方业务写接口；词库维护仍限管理员。

### 阶段 D：HR 原创职业观点帖

2026-11-22 按端拆分实施：第一阶段仅 HR 创作与后端已完成；下一阶段接运营审核，再接公开阅读与学生互动。当前帖子提交后统一待审核，不会自动公开。细节见 [HR原创帖子分阶段开发](HR原创帖子-分阶段开发.md)。

- 先确定独立数据对象、接口、审核和展示契约，再增加新迁移。
- 实现 HR 发帖、查看自己的帖子与状态；学生和游客仅看已发布内容。
- 实现与帖子契约匹配的点赞、收藏、举报及运营处理。
- 观点帖不等于学生提问，不授予 HR 创建学生问题或发起学生追问的权限。

## 4. 验收场景

1. 游客可浏览已发布内容，读取审核中或已下架内容不会泄露正文。
2. 学生登录后提问，需人工审核的内容经运营通过后进入公开列表。
3. 任一 HR 提交回答后，问题离开待回答池；审核中的回答不计入公开回答数。
4. HR 回复指定学生追问，详情与时间线保留关联；返回工作台保留当前分类和位置。
5. 撤销、下架、无数据分页、重复提交与接口失败均有确定结果。
6. 学生、HR、运营、管理员和游客的越权请求被后端拒绝。
7. 举报处理与审核记录写入真实后端，不以浏览器本地状态代替。

## 5. 完成标准

- 需求与当前范围一致，现行文档无已停用流程的开发或验收要求。
- 后端构建和相关流程测试通过，前端类型检查和生产构建通过。
- 影响多个模块的改动完成端到端联调；新增数据库结构已验证迁移。
- 接口契约、OpenAPI、启动和演示说明与代码一致。
- 任务分支提交 PR，并经另一位人类成员审查后合入 main。
- 真实短信、认证、大模型审核、消息通知等未完成项明确标记，不用占位页面冒充完成。
