## 一、项目名字

**推荐主名称：职问桥**

| 名称 | 含义 | 适合场景 |
|---|---|---|
| 职问桥 | 学生的问题与 HR 的经验之间的一座桥，公开、异步、可沉淀 | **推荐主品牌** |
| 职答 | 职场人回答职业问题，简洁直接 | 产品名 / 小程序名 |
| 职场回声 | HR 的观点被学生看见、点赞、回应，形成回声 | 内容社区感更强 |
| 前辈请回答 | 突出「HR / 职场前辈—学生」的问答关系 | 活动感强，适合冷启动 |
| 职途问答库 | 强调结构化、可检索、可沉淀 | 偏工具和资料库 |

- **Slogan**：让好问题遇见对的人，让经验公开沉淀。
- **定位一句话**：面向大学生与 HR 的公开、异步、结构化职业问答信息库，不做私聊社交。

## 二、项目概述

「职问桥」是一个连接大学生与 HR / 职场人的职业发展问答平台。HR 可以公开发表职业发展、企业人力资源管理、招聘面试、行业选择等观点，也可以选择回答学生提出的公开问题；学生可以提问、点赞、收藏、标记「有用」，但不与 HR 进行一对一私聊。

产品核心不是「社交」，而是「公开问答库」：所有互动发生在公开页面或指定话题下，内容可审核、可沉淀、可检索，从而降低 UGC 平台的监管与运营风险。

## 三、背景与问题

具备双边资源：一端是大量熟悉职业发展和企业人力资源管理的 HR，另一端是大量有职业困惑的学生。双方有交流意愿，但直接面对面或私聊存在平台监管、隐私、安全、内容不可控等问题。

因此需要把「直接对话」转化为「公开异步互动」：

1. 学生公开提问；
2. HR 选择回答；
3. 学生点赞、收藏、追问；
4. 优质内容被精选和沉淀；
5. 平台方对公开内容进行审核和干预。

## 四、产品定位

- **产品名**：职问桥
- **产品形态**：公开、异步、结构化的职业问答信息库
- **核心用户**：大学生、HR / 职场答主、平台运营方
- **明确不做**：私信、好友、实时聊天、匿名树洞、招聘投递、简历交易、付费咨询

**核心价值**：

- 对学生：获得真实职场人的公开经验，降低信息差；
- 对 HR：低成本表达观点、建立个人专业形象、影响潜在人才；
- 对平台：形成可审核、可沉淀、可复用的职业发展内容库。

## 五、核心机制

- **学生端**：发布问题 → 选择标签 → 等待 HR 回答 → 点赞/收藏/标记有用 → 可对回答进行公开追问。
- **HR 端**：浏览开放问题 → 选择愿意回答的问题 → 发布回答；也可主动发布「观点帖」或「话题征集」。
- **平台端**：审核内容 → 精选问答 → 运营话题 → 处理举报 → 维护答主。

**关键原则**：所有互动公开、异步、留痕、可审核；不提供任何一对一私密对话入口。

## 六、功能规划

### MVP 阶段功能

1. **学生提问**：问题标题、描述、标签（面试准备、简历、行业选择、实习、职业规划等）、是否公开。
2. **HR 回答**：HR 浏览问题池，选择回答；回答支持「一句话建议」和「详细经验」两种长度。
3. **HR 观点帖**：HR 可主动发布短观点或经验分享，学生点赞、收藏。
4. **互动信号**：点赞、收藏、「有用」标记；不做「踩」和公开负面评分。
5. **精选问答**：运营根据点赞、收藏和内容质量生成「本周精选」。
6. **举报与审核后台**：举报入口、禁用词库、AI 初筛、人工复核、下架与封禁。
7. **身份认证**：HR 在职/企业身份认证；学生手机号实名，学校专业可选填。
8. **搜索与标签**：按标签浏览问答，形成初步内容库。

### 后续功能

- HR 发起话题讨论，学生参与回应；
- 问答合集与专题页；
- 「HR 观点征集—学生回应—HR 再回应」的循环话题；
- 内容收藏夹与个人成长记录；
- 数据看板：问题回应率、回答时长、精选内容表现。

## 七、用户流程

**学生流程**
注册/认证 → 浏览精选问答 → 发布问题并选择标签 → 等待回答 → 点赞/收藏/追问 → 形成个人收藏。

**HR 流程**
认证 → 浏览问题池或话题 → 选择回答/发布观点 → 获得点赞和「有用」反馈 → 进入精选答主池。

**运营流程**
审核新内容 → 匹配问题与 HR → 推动 24—48 小时内回应 → 精选优质内容 → 处理举报与风险内容。

## 八、合规与审核设计

- **实名与身份核验**：HR 需任职企业或职业身份认证；学生至少手机号实名，教师邀请码可作为初始可信入口。
- **内容审核**：AI 初筛 + 人工复核；建立禁用词库，重点拦截政治敏感、就业歧视、虚假招聘、人身攻击、隐私泄露。
- **数据最小必要**：只收集手机号和必要身份标识；公开页面 HR 可展示为「某互联网公司 HR」，不暴露真实姓名。
- **未成年人保护**：如涉及未满 18 岁学生，增加内容限制和监护人/学校相关合规提示。
- **免责声明**：明确平台为职业发展交流项目，不代表学校官方就业指导平台；回答为个人观点，不构成招聘承诺。
- **应急机制**：举报处理时限、违规内容下架、账号封禁、重大风险人工介入。

> 具体合规要求建议在上线前咨询法律或平台合规专业人士。

## 九、冷启动方案

**第一阶段：邀请制跑通闭环**

- 从认识的 HR 中邀请 10—15 位愿意分享、表达清晰的「首批答主」；
- 从学生中邀请 1—2 个学院或专业的学生；
- 由运营方先抛出第一批高质量问题，定向邀请 HR 回答；
- 核心指标不是用户数，而是「学生问题能否在 24—48 小时内得到至少一个有效回答」。

**第二阶段：内容沉淀与开放注册**

- 形成 100 条以上真实问答后，开放学生注册；
- 用「本周精选」「热门标签」「HR 观点帖」做内容运营；
- 逐步扩大 HR 答主池，保持回答供给。

## 十、指标体系

**核心指标**

- 问题回应率：发布问题中获得至少 1 个 HR 回答的比例；
- 首次回应时长：目标 24—48 小时内；
- 有效回答率：被点赞/收藏/标记有用的回答比例；
- 次周留存：学生和 HR 的周活跃留存；
- 举报处理时长；
- 精选内容数量与收藏量。

**冷启动成功标准**

- 4 周内，80% 以上学生问题在 48 小时内获得至少 1 个 HR 回答；
- 8 周内，沉淀 100 条以上公开问答；
- 首批 HR 答主中，至少 60% 愿意持续参与；
- 无重大内容安全事故。

## 十一、路线图

| 阶段 | 时间 | 重点 |
|---|---|---|
| MVP 开发 | 第 1—4 周 | 提问、回答、观点帖、点赞收藏、审核后台 |
| 冷启动 | 第 5—8 周 | 邀请 10—15 位 HR、1—2 个学院学生，跑通回应闭环 |
| 内容沉淀 | 第 9—12 周 | 精选问答、标签体系、话题讨论、搜索优化 |
| 扩展 | 第 13 周起 | 扩大 HR 答主池、开放注册、形成专题内容库 |

## 十二、团队与资源

- **项目负责人**：用户本人，负责双边资源、定位和内容把关；
- **产品/运营**：1 人，负责问题匹配、内容审核、精选运营；
- **技术**：小程序或轻量 Web 外包/兼职开发；
- **审核**：初期由运营兼任，后期引入兼职审核。

预算重点：开发工具、审核人力、内容运营、合规咨询。初期不必做大平台，先做轻量小程序或 Web 端。

## 十三、主要风险与应对

| 风险 | 应对 |
|---|---|
| HR 参与不足 | 首批邀请制，降低回答成本，设置「一句话建议」 |
| 学生提问质量低 | 提供提问模板和标签，运营筛选后发布 |
| 内容合规风险 | 公开异步、AI 初筛 + 人工复核、禁用词库、举报机制 |
| 被误认为学校官方平台 | 明确个人发起项目定位，避免使用学校官方名义 |
| 变成招聘或私聊工具 | 产品层面不设私信、不设简历投递、不设付费咨询 |

## 十四、结论

「职问桥」把「不让直接对话」从合规妥协升级为产品定义：不做社交，做公开、异步、结构化的职业问答库。先用手上 HR 和学生资源跑通「一个问题必有回应」的最小闭环，再逐步沉淀内容、扩大答主池。这个路径轻、可控、可审核，适合作为项目的起步形态。
