# HR 站内通知

2026-11-21。第一版面向 HR，提供持久化站内通知、分类列表、未读红点、单条/全部已读及关联内容定位。学生通知、点赞通知、短信、邮件和系统推送另行开发。

## 触发与接收范围

| 事件 | 收件人 | 点击目标 |
|---|---|---|
| 学生追问发布 | 具体主回答的目标 HR | 展开并高亮对应追问，待回复时选中该追问 |
| HR 回答或追问回复人工审核通过 | 内容作者 | 具体回答/回复；内容后续失效时转本人记录 |
| HR 回答或追问回复人工审核驳回 | 内容作者 | 个人中心中对应的单条记录 |
| 运营直接下架或举报处理下架 | 内容作者 | 个人中心中对应的单条记录 |

普通回答立即发布、机器即时拦截、作者主动撤销不另生成通知；已有请求页面提示保留。通知从功能启用后的业务操作开始，不为既有内容批量补发。

追问通知只发给被追问的 HR，不广播给同题其他 HR。直接发布和人工审核后发布共用事件入口。审核与下架通知说明使用面向作者的通用文案，内部审核/举报备注不直接公开；详细公开原因字段可在运营页面实现时另定。

## 数据、权限和一致性

- V16 增加 `hr_notifications`：接收人、事件唯一键、类型、分类、关联问题/回答/追问 ID、创建时间、阅读时间。数据库唯一约束防止重复处理产生重复通知。
- 通知写入与追问发布、审核或下架共用业务事务，失败一起回滚；阅读通知不修改回答或追问状态、不消除工作台待办。
- 不存原问题/回答/追问正文快照，不存内部审核备注。读取和点击时重新校验内容可见性：隐藏问题不返回标题，追问失效显示“相关内容已不可查看”，已下架回答跳转本人安全记录，不把隐藏正文重新公开。
- 每个接口只允许 HR，并从登录会话取接收人；其他 HR 无法读取或标记别人的通知，越权标记及查看回答记录返回 404。
- 全部已读提交列表加载时的 `snapshotId`，仅标记该编号之前的本人消息；操作期间新生成的消息继续保持未读。

## 接口

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/v1/hr/notifications?category=all&unreadOnly=false&cursor=&limit=5` | 分类、未读和 ID 倒序分页 |
| GET | `/api/v1/hr/notifications/unread-count` | 全部/追问/系统未读计数与快照编号 |
| POST | `/api/v1/hr/notifications/{id}/read` | 幂等标记本人通知已读，返回当前可见性与跳转目标 |
| POST | `/api/v1/hr/notifications/read-all` | `{ "throughId": snapshotId }`，按快照批量标记已读 |
| GET | `/api/v1/hr/answers/{id}` | 当前 HR 的单条回答安全记录，复用本人列表的脱敏规则 |

分类 `category=all|followup|system`，`limit=1..50`，游标为正整数。列表返回 `items`、`nextCursor`、`snapshotId`，无下一页时游标为空或省略。计数返回 `total`、`followup`、`system`、`snapshotId`。

通知包含 `id`、`type`、`category`、`title`、`message`、可见时的 `questionTitle`、关联编号、`destination`、`createdAt`、`readAt`。`destination=question|answer_record|unavailable` 由后端判断，前端不凭历史文案推断。单条已读不会反复改写第一次阅读时间。

## 页面与刷新

- 独立 HR 消息页 `/hr/messages`：全部消息、学生追问、审核与系统通知，可只看未读，每页五条，末页禁用下一页，空页返回第一页。
- HR 顶部使用真实计数，超过 99 显示 99+；登录、路由变化、窗口重新获得焦点、菜单打开和可见页面约每 30 秒刷新。隐藏页面不轮询，退出/切换账号清空旧计数并丢弃旧响应。
- 点击通知成功标记已读后定位具体内容；已经处理的追问仍可定位，单纯看消息不等于回复。相关目标失效时保留说明和标为已读入口。
- 进入详情或个人记录后可返回消息中心，保留分类、未读筛选、页码和滚动位置。审核/下架通知通过单条回答接口直接定位，不扫描所有分页。
- 个人页的通知记录模式提供“查看全部记录”；原 HR 工作台接口和学生页面保持原语义。顶部共享组件仅新增 HR 分支，学生静态菜单留给学生端负责人接入。
