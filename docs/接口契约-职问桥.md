# 《职问桥》前后端接口契约 v1

> 项目代号：**CareerQ**　｜　对外名称：**职问桥**
> 编写：**DeepSeek**（AI 协助）　｜　日期：2026-11-14　｜　状态：**草案 v1.1（供前后端联调）**
> 适用：后端 **Spring Boot**（用户负责前后端连接）＋ 前端 **Vue3 + TypeScript**（队友负责）
> 已定：**鉴权采用 Cookie 会话 + CSRF Token**；Qoder Sites 暂按「只托管前端静态资源」推进。
> 方法：本文件是前后端唯一契约；**以本文件 + OpenAPI 文档为准，前端不得依赖后端内部实现**。

---

## 0. 约定

| 项 | 约定 |
|---|---|
| 基础路径 | `/api/v1` |
| 数据格式 | JSON，UTF-8；时间 ISO-8601（如 `2026-11-14T17:20:00+08:00`） |
| 鉴权 | **会话 Cookie（已定）**：`HttpOnly; Secure; SameSite=Lax` + CSRF Token；不使用 localStorage 存令牌 |
| 分页 | 游标分页：`?cursor=<opaque>&limit=20`（当前实现为上一页最后一条 id）；响应 `{items:[], nextCursor:null}` |
| 幂等 | 契约预留 `Idempotency-Key`；**后端当前尚未强制实现**，前端重试请自行防抖 |
| 错误体 | `{ "code": 40400, "message": "问题不存在", "data": null }`（code 为数字，见联调指南 §4） |
| 状态码 | 200/201 成功；400 参数错误；401 未登录；403 无权限；404 不存在；409 冲突；429 限流；500 服务异常；503 暂不可用 |
| 角色 | `student` / `hr` / `operator` / `admin` |
| CORS | 仅允许前端域名；本地开发用 dev server 代理 `/api` 到 Spring Boot |

## 1. 鉴权与用户

先请求 `GET /api/v1/auth/csrf`，保留响应 Cookie，并将响应中的 `token` 放入 `X-XSRF-TOKEN` 请求头。发送验证码、登录、注册和登出均要求此令牌。

### POST `/api/v1/auth/sms-code`
请求手机验证码。开发环境使用固定验证码。生产环境在接入真实短信前，发送验证码、登录及注册返回 **503 / code 50301**。短信发送限流尚未实现。
```json
{ "phone": "13800000000" }
```

### POST `/api/v1/auth/login`
**已注册用户**手机号 + 验证码登录，成功返回会话 Cookie。
未注册手机号返回 **404 / code 40401**（前端应引导去注册）。
```json
{ "phone": "13800000000", "code": "123456" }
```
响应：
```json
{ "user": { "id": "u_1", "role": "student", "nickname": "小明" } }
```

> **dev 环境验证码固定为 `123456`**（不发送真实短信）。生产环境默认关闭固定验证码。

### POST `/api/v1/auth/register`
注册新用户（默认学生角色），成功后直接建立会话。
**只有手机号 + 验证码必填**；昵称、学校、专业、年级均可选（昵称不填自动生成「用户1234」）。
```json
{ "phone": "13800000000", "code": "123456", "nickname": "小明",
  "school": "某大学（可选）", "major": "计算机（可选）", "grade": "大三（可选）",
  "role": "student | hr（可选，默认 student）" }
```
响应同登录：`{ "user": { "id": 1, "role": "student", "nickname": "小明" } }`
手机号已注册返回 **409 / code 40901**。`role=hr` 注册后直接为 HR 角色（真实在职认证暂缓）。

### POST `/api/v1/auth/logout`
注销当前会话。

### POST `/api/v1/auth/hr-verify`
提交 HR 认证材料（multipart 或 JSON 引用存储 ID）。
```json
{ "companyDisplay": "某互联网公司", "industry": "互联网", "position": "HRBP", "materialRef": "storage_xxx" }
```
响应：`{ "verifyStatus": "pending" }`

### GET `/api/v1/me/profile`（可选完善资料）
返回学历信息 + 实习/项目经历；所有字段均可空。
```json
{ "id":1, "nickname":"小明", "school":"某大学", "major":"计算机", "grade":"大三",
  "degree":"本科", "graduationYear":"2027",
  "experiences":[{ "id":1, "type":"internship", "title":"某公司", "role":"后端实习生",
                   "startDate":"2025-06", "endDate":"2025-09", "description":"..." }] }
```
`type`：`internship`（实习）/ `project`（项目）。

### PUT `/api/v1/me/profile`（可选完善资料）
整体保存学历信息与经历（经历为覆盖式保存，传空数组即清空）。
```json
{ "school":"某大学", "major":"计算机", "grade":"大三", "degree":"本科",
  "graduationYear":"2027",
  "experiences":[{ "type":"internship", "title":"某公司", "role":"后端实习生",
                   "startDate":"2025-06", "endDate":"2025-09", "description":"..." }] }
```

### GET `/api/v1/me`
当前用户信息与角色。
```json
{ "id":"u_1","role":"student","nickname":"小明","school":"某大学","major":"计算机","hrVerifyStatus":null }
```

## 2. 问题（公开 / 私密）

### POST `/api/v1/questions`
提问，`scope` 决定公开或私密。私密问题提交后进入 `pending_human`，审核通过才进入 HR 待认领池。
```json
{
  "scope": "public",
  "title": "实习面试一般会问什么？",
  "body": "……",
  "tags": ["实习", "面试准备"]
}
```
响应：`{ "id": "q_1", "status": "pending_machine" }`

### GET `/api/v1/questions?scope=public&tag=实习&cursor=&limit=20`
公开问题列表（仅 `published`）。

### GET `/api/v1/questions/mine?scope=private`
我的问题（含私密 Q1..Qn 与状态）。需登录。

### GET `/api/v1/questions/{id}`
问题详情。私密问题仅作者、指派 HR、运营可读。指派 HR 只能查看已通过审核的问题。待审或被拒的回答与追问只显示给各自的提交者，运营通过审核队列查看待审内容。

### POST `/api/v1/questions/{id}/followups`
追问（公开或私密按问题 scope）。私密工单仅在已认领且未结单时允许双方提交追问。私密追问返回 `pending_human`，通过审核后向对方展示。
```json
{ "body": "那简历应该写几页？" }
```

### POST `/api/v1/questions/{id}/close`
提问者确认结单。私密工单必须有审核通过的回答，且无待审核回答。结单自动提交问题和最近一条通过审核的回答，状态变为 `public_pending`。审核通过后进入 `public_archived`，公开稿出现在 `GET /api/v1/posts`。

### POST `/api/v1/questions/{id}/publish`
仅作者调用，用于提交旧版已关闭工单或重提审核未通过的公开稿。请求无需正文。

## 3. HR 问题池与回答

### GET `/api/v1/hr/question-pool?tag=&cursor=`
公开未回答/待回答池（按时间排序）。

### GET `/api/v1/hr/private-pool?cursor=`
私密待认领池（展示脱敏摘要，不含提问者身份）。

### POST `/api/v1/hr/questions/{id}/claim`
认领私密问题 → `assigned_hr_id = 当前 HR`。

### POST `/api/v1/questions/{id}/answers`
回答问题（公开或私密）。私密回答由指派 HR 提交，返回 `pending_human`。审核通过后提问者可见。
```json
{ "body": "……", "lengthType": "detailed" }
```
`lengthType`: `one_liner` | `detailed`。

## 3.1 提问权限
- `POST /api/v1/questions` **仅 `student` 角色**可调用；HR/运营/管理员返回 403/40300。
- HR 注册后进入 HR 工作区（问题池/私密池/回答），前端不展示「提问」入口。

## 4. 互动与内容

### POST `/api/v1/interactions`
点赞 / 收藏 / 标记有用（幂等：重复点击不重复计数）。
```json
{ "targetType": "question", "targetId": 1, "type": "like" }
```
- `targetType`：`question` / `answer` / `post`
- `type`：`question`、`answer` 支持 `like` / `useful` / `favorite`；`post` 只支持 `like` / `favorite`

### DELETE `/api/v1/interactions`
取消点赞 / 有用 / 收藏（幂等；请求体同 POST）。

### GET `/api/v1/me/favorites?targetType=&cursor=&limit=`
我的收藏列表（按收藏时间倒序，游标分页）。
```json
{ "items": [{ "targetType":"question", "targetId":1, "title":"...", "excerpt":"...", "createdAt":"..." }],
  "nextCursor": null }
```

### 互动状态（随详情返回）
- `GET /api/v1/questions/{id}` → `data.viewer: { liked, usefuled, favorited }`；每个回答带 `liked` / `usefuled`
- `GET /api/v1/posts`、`/feed/highlights` → 每条带 `liked` / `favorited`
- 问题/回答/观点帖均带 `likeCount`、`usefulCount` 计数

### GET `/api/v1/posts?cursor=` / POST `/api/v1/posts`
观点帖列表 / 发布（HR）。

### GET `/api/v1/feed/highlights`
本周精选。

### POST `/api/v1/reports`
举报。
```json
{ "targetType": "answer", "targetId": "a_1", "reason": "spam", "detail": "..." }
```

## 5. 运营后台（RBAC：operator / admin）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/moderation/queue` | 问题、回答、追问及公开稿的待审队列，返回全文 `body`，公开稿另有 `hrAnswer` |
| POST | `/api/v1/admin/moderation/{targetType}/{id}/decide` | `{ "decision": "approve"\|"reject"\|"remove", "note": "..." }` |
| GET/POST | `/api/v1/admin/moderation/words` | 词库查询 / 新增或更新 |
| GET | `/api/v1/admin/reports?status=pending` | 举报队列 |
| POST | `/api/v1/admin/reports/{id}/handle` | `{ "decision": "dismiss"\|"remove", "note": "..." }` |
| GET | `/api/v1/admin/metrics` | 待审/已发布/举报积压计数 |
| GET | `/api/v1/posts` | 已审核公开沉淀列表 |
| GET | `/api/v1/feed/highlights` | 本周精选（已审核公开帖 Top10） |
| GET | `/api/v1/admin/private/{id}` | 审阅私密内容（**写审计日志**） |

审核员批准 `public_post` 时，可以在决定请求中附上 `publicCopy`（含 `title`、`questionBody`、`hrAnswer`）替换公开稿，移除正文中的个人识别信息。公开稿审核通过后公开，原工单按私密权限访问。

## 7. 状态枚举（前后端共用）

- `Question.status`：公开问题 `pending_machine` / `pending_human` / `published` / `rejected` / `removed`。私密问题从 `pending_human` 经 `open`（待认领）、`assigned`（已认领）进入 `public_pending`（已结单，公开稿待审核），审核结果为 `public_archived` 或 `public_rejected`。`closed` 为旧版结单状态。
- `scope`：`public` / `private`
- `Answer.lengthType`：`one_liner` / `detailed`
- `HR verifyStatus`：`pending` / `verified` / `rejected`

## 8. 前后端联调流程（建议）

1. 后端先用 springdoc 生成 OpenAPI（`/v3/api-docs`、`/swagger-ui`），前端据此生成类型与 mock。
2. 前端本地 dev server 代理 `/api` → `http://localhost:8080`，避免 CORS。
3. 契约变更**先改本文件**并在 PR 说明，前后端同步评审，禁止后端单方面改字段。
4. 联调顺序：鉴权 → 公开列表/详情 → 提问 → HR 回答 → 互动 → 私密工单 → 审核后台。
