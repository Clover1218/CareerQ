## 0. 约定

| 项 | 约定 |
|---|---|
| 基础路径 | `/api/v1` |
| 数据格式 | JSON，UTF-8；时间 ISO-8601（如 `2026-11-14T17:20:00+08:00`） |
| 鉴权 | **会话 Cookie（已定）**：`HttpOnly; Secure; SameSite=Lax` + CSRF Token；不使用 localStorage 存令牌 |
| 分页 | 游标分页：`?cursor=<opaque>&limit=20`（当前实现为上一页最后一条 id）；响应 `{items:[], nextCursor:null}` |
| 幂等 | 契约预留 `Idempotency-Key`；**后端当前尚未强制实现**，前端重试请自行防抖 |
| 错误体 | `{ "code": 40400, "message": "问题不存在", "data": null }`（code 为数字，见联调指南 §4） |
| 状态码 | 200/201 成功；400 参数错误；401 未登录；403 无权限；404 不存在；409 冲突；429 限流；500 服务异常；503 暂不可用 |
| 角色 | `student` / `hr` / `operator` / `admin` |
| CORS | 仅允许前端域名；本地开发用 dev server 代理 `/api` 到 Spring Boot |

## 1. 鉴权与用户

统一请求层先获取 `GET /api/v1/auth/csrf`，保留 Cookie，并在内容写请求中将 `token` 放入 `X-XSRF-TOKEN`。认证路径的 CSRF 豁免以 `SecurityConfig` 为准；角色和对象归属检查始终由后端执行。

学生页面在非认证写请求中附带 `X-CareerQ-Student-Id`，值为发起操作时页面所显示的学生 ID；此头仅检查会话是否已切换，不参与身份认证。若与真实会话身份不一致（含切到其他角色），返回 **409 / code 40902**，提示“登录身份已变化，请确认当前账号后重新操作”，本次业务不执行，也不自动以新账号重试。未携带此头的客户端继续接受既有会话、角色和归属检查。前端在登录、注册、退出时广播不含身份资料的会话变化信号，学生标签页在可见、恢复焦点和进入受保护路由时刷新身份；切号后清空旧学生页面与表单。

### POST `/api/v1/auth/sms-code`
请求手机验证码。开发环境使用固定验证码。生产环境在接入真实短信前，发送验证码、登录及注册返回 **503 / code 50301**。短信发送限流尚未实现。
```json
{ "phone": "13800000000" }
```

### POST `/api/v1/auth/login`
**已注册用户**手机号 + 验证码登录，成功返回会话 Cookie。
未注册手机号返回 **404 / code 40401**（前端应引导去注册）。
```json
{ "phone": "13800000000", "code": "123456" }
```
响应：
```json
{ "user": { "id": 1, "role": "student", "nickname": "小明" } }
```

> **dev 环境验证码固定为 `123456`**（不发送真实短信）。生产环境默认关闭固定验证码。

### POST `/api/v1/auth/register`
注册新用户（默认学生角色），成功后直接建立会话。学生只需手机号与验证码，昵称可选；选填的 `school`、`major`、`grade` 会一并保存，分别最多 128、128、32 字，空白归为空值，之后从 `/me`、`/me/profile` 读取或继续编辑。HR 可通过后端注册契约传 `role=hr`，并必须提供 `company`，`industry` 与 `position` 可选；学生教育字段不写入 HR 账号。真实 HR 认证仍待开发。
```json
{ "phone": "13800000000", "code": "123456", "nickname": "小明", "school": "某大学", "major": "计算机", "grade": "大三" }
```
响应同登录：`{ "user": { "id": 1, "role": "student", "nickname": "小明" } }`
手机号已注册返回 **409 / code 40901**。

### POST `/api/v1/auth/logout`
注销当前会话。

前端登录、注册相互切换时必须保留站内 `redirect`（包括查询参数和锚点）；未注册手机号自动转注册也需传递该值。登录或注册成功返回原操作页面，例如游客从 `/ask` 进入认证，成功后回 `/ask`。缺少或不合法的返回值回首页，不接受外站地址或认证页循环。

### GET `/api/v1/me/profile`（可选完善资料）
返回学历信息 + 实习/项目经历；所有字段均可空。
```json
{ "id":1, "nickname":"小明", "school":"某大学", "major":"计算机", "grade":"大三",
  "degree":"本科", "graduationYear":"2027",
  "experiences":[{ "id":1, "type":"internship", "title":"某公司", "role":"后端实习生",
                   "startDate":"2025-06", "endDate":"2025-09", "description":"..." }] }
```
`type`：`internship`（实习）/ `project`（项目）。

### PUT `/api/v1/me/profile`（可选完善资料）
整体保存学历信息与经历（经历为覆盖式保存，传空数组即清空）。
```json
{ "school":"某大学", "major":"计算机", "grade":"大三", "degree":"本科",
  "graduationYear":"2027",
  "experiences":[{ "type":"internship", "title":"某公司", "role":"后端实习生",
                   "startDate":"2025-06", "endDate":"2025-09", "description":"..." }] }
```

### GET `/api/v1/me`
当前用户信息与角色。
```json
{ "id":1,"role":"student","nickname":"小明","avatarUrl":null,"school":"某大学","major":"计算机","grade":"大三" }
```

## 2. 公开问题、学生追问与撤回

### POST `/api/v1/questions`
仅学生可提问。`scope` 只接受 `public`（可省略使用默认值），其他值返回 40001。内容经过规则审核后发布、进入人工审核或被拒绝。
```json
{
  "scope": "public",
  "title": "实习面试一般会问什么？",
  "body": "……",
  "tags": ["实习", "面试准备"]
}
```
响应包含问题对象和真实 `status`；普通内容可直接返回 `published`，需人审时返回 `pending_human`。

### GET `/api/v1/questions?tag=实习&cursor=&limit=20`
公开问题 feed（仅 `published`），按时间倒序。返回完整正文但不含作者；前端固定按行折叠展示，每张卡片都提供「阅读全文」，展开后再调 `/content` 获取作者与发布时间。
```json
{ "items": [{
    "id": 1, "title": "实习面试一般会问什么？",
    "excerpt": "第一次找实习，想提前准备……",
    "tags": ["实习"],
    "answerCount": 1, "followupCount": 2, "replyCount": 3,
    "likeCount": 0, "favoriteCount": 0,
    "createdAt": "2026-11-15T22:54:00"
  }],
  "nextCursor": null }
```
`excerpt` 为完整正文，不做字数截断；`replyCount` 为 HR 回答与追问合计。该接口固定按时间倒序，对应前端「最新」。

### GET `/api/v1/feed/questions?sort=recommend&q=&tags=&tagMode=and&period=&from=&to=&cursor=&limit=20`
公开问题列表，匿名可访问。不传新参数时等价于原推荐流：可选登录，游客按「质量 + 新鲜度」排序，登录用户按标签偏好 + 质量 + 新鲜度排序。仅返回 `published` 公开问题，并排除当前用户标记「不感兴趣」的问题。

筛选参数（均可选、可组合）：
- `q`：标题 + 正文关键词，不区分大小写，最长 50 字。
- `tags`：逗号分隔的标签 `slug`，最多 10 个；旧参数 `tag` 仍兼容，等价于单标签。
- `tagMode`：`and`（默认，需命中全部标签）或 `or`（命中任一标签）。
- `period`：`day` / `week` / `month` / `all`（默认），按问题 `createdAt` 的滚动窗口计算。
- `from` / `to`：自定义时间范围，接受 `YYYY-MM-DD` 或 `YYYY-MM-DDTHH:mm:ss`；结束日期含当天；跨度不超过 366 天。传任一项时忽略 `period`。

排序 `sort`：
- `recommend`（默认）：标签偏好 + 质量 + 新鲜度，返回 `matchedTags` 推荐理由。
- `latest`：按 `createdAt`、`id` 倒序。
- `hot`：加权互动（点赞 1、收藏 3、有用 1.5、回答与追问合计 2，另加 1 分基线）× 7 天半衰期，在近 180 天候选池内排序。

`cursor` 为不透明字符串，**绑定排序与全部筛选条件**；切换筛选或排序后必须丢弃旧游标，否则返回 400（`40001`）。`limit` 1–50，默认 20。
```json
{ "items": [{
    "id": 1, "title": "实习面试一般会问什么？",
    "excerpt": "第一次找实习，想提前准备……",
    "tags": ["实习", "面试准备"],
    "answerCount": 1, "followupCount": 2, "replyCount": 3,
    "likeCount": 0, "favoriteCount": 0,
    "createdAt": "2026-11-15T22:54:00",
    "matchedTags": ["实习"],
    "viewer": { "liked": false, "usefuled": false, "favorited": false, "disliked": false }
  }],
  "nextCursor": "djI6cmVjb21tZW5kOjEyMzQ1Njc4OToxNzYzMzgwODAwOjEwMjQwOjk4NzY1OjA" }
```
`matchedTags` 仅在 `recommend` 下可能有值，为命中正向偏好的前 2 个标签名；游客、无偏好或其它排序时为空数组。参数非法（`sort`/`tagMode`/`period` 枚举、`from` 不早于 `to`、跨度超限、标签超过 10 个、关键词超长、游标与条件不匹配）统一返回 400（`40001`）。

三种排序均返回每条问题的当前会话 `viewer` 互动状态，游客全部为 false；与公开的总计数相互独立，不返回其他用户的标记或身份。后端对当前页批量查询，不按卡片逐条请求。前端首次显示即用服务端状态恢复点赞/收藏，刷新、重登及切号后重新读取；无 `viewer` 的旧摘要/本人列表通过可见卡片的内容接口读取，不把本地按钮状态当作持久化来源。

### GET `/api/v1/questions/mine?scope=public`
当前学生的公开问题与状态。需登录，只返回本人有权查看的内容；也可通过 `GET /api/v1/me/questions` 查询。

### GET `/api/v1/questions/{id}`
已发布公开问题游客可读。问题作者可查看本人允许展示的审核状态；待审或被拒的回答只对各自提交者展示，运营从审核队列读取上下文。

### GET `/api/v1/questions/{id}/content`
展开全文。公开问题返回完整 `body` 与作者；非公开问题返回 404。登录用户附带 `viewer` 互动状态。
```json
{ "question": {
    "id": 1, "scope": "public", "status": "published",
    "title": "……", "body": "完整正文", "tags": ["实习"],
    "author": { "id": 2, "nickname": "演示学生" },
    "createdAt": "2026-11-15T22:54:00",
    "answerCount": 1, "followupCount": 2, "usefulCount": 0,
    "likeCount": 0, "favoriteCount": 0, "firstAnswerAt": null
  },
  "viewer": { "liked": false, "usefuled": false, "favorited": false, "disliked": false } }
```

### GET `/api/v1/questions/{id}/thread`
回答区。把 HR 主问题回答、HR 对追问的回复与学生 FollowUp 放入时间线，按 `createdAt`、`kind`、`id` 排序。每条主回答按其回答 ID 独立展示，同一 HR 可提交多条主回答；不能按 HR ID 覆盖旧回答。主回答固定按发布时间正序，后发的在下，不提供回答热度排序。追问通过必填 `rootAnswerId` 归入对应主回答，`hrId` 保留目标 HR 权限校验；追问回复通过 `followupId` 关联原追问。仅返回关联具体主回答的追问与回复，不提供未指定回答的额外分区。非公开问题返回 404。

主回答或学生追问撤销/下架后，如果仍有可见的关联讨论，接口返回必要占位：`status=removed`、`body=""`，隐藏内容的互动计数归零、本人互动标记为 false。占位内容不得参与新追问、点赞或举报；原有下级讨论独立按其状态展示，仍可回复已发布且发给本人的旧追问。没有可见下级内容的隐藏记录继续不返回。

HR 回答与追问回复另返回 `removalSource`：`author` 表示作者主动撤销，`operator` 表示运营直接下架或举报处理下架，`unknown` 表示无法确认来源的旧移除记录；未移除时为空或省略。适用于详情 `answers`、时间线回答项和 HR 工作台 `myAnswer`，不用于推断学生追问的来源。前端对应显示“作者已撤销”“运营已下架”“已移除”。操作者 ID 与移除时间仅在后端保存，不在公开接口暴露；隐藏正文仍保持为空，HR 本人摘要也返回空正文。

`answerCount` 保留既有已发布 HR 回答记录总数（含追问回复），`followupCount` 为已发布学生追问数，`replyCount` 为二者合计；本次不更改这些既有字段语义。界面总计称“问答互动”，展开后单独统计已发布主回答数量及去重后的 HR 人数，占位和待审内容不计入公开主回答数。
```json
{ "items": [{
    "key": "answer-1", "kind": "hr_answer", "id": 1,
    "body": "实习经历不是硬性门槛……",
    "author": { "id": 4, "nickname": "某互联网公司 HR", "company": "某互联网公司", "position": "HR" },
    "hr": true, "status": "published",
    "likeCount": 0, "liked": false,
    "createdAt": "2026-11-15T22:56:00"
  }],
  "viewer": { "liked": false, "usefuled": false, "favorited": false, "disliked": false },
  "answerCount": 1, "followupCount": 2, "replyCount": 3 }
```
`kind`：`hr_answer`（HR 主问题回答，可点赞/举报）| `followup_answer`（HR 对指定追问的回复，可点赞/举报）| `followup`（学生追问，仅支持回复定位，不落库点赞/举报）。

### POST `/api/v1/questions/{id}/followups`
学生追问。仅题主本人可对已发布公开问题提交；其他学生、HR、运营和管理员不能提交追问。必须从具体回答下发起，同时传正整数 `rootAnswerId` 和该回答作者的 `hrId`；缺少具体回答时返回 HTTP 400、业务码 40001。后端校验目标属于当前问题、是已发布主回答、作者与目标 HR 相同，不允许把追问挂到其他问题、其他 HR 或追问回复下面。
```json
{ "hrId": 4, "rootAnswerId": 108, "body": "那简历应该写几页？" }
```

追问复用问题/回答的规则审核：返回的 `status` 为 `published`、`pending_human` 或 `rejected`。只有 `published` 对公众及目标 HR 可见、计入 `followupCount` 并通知目标 HR；待审/驳回仅提交者可从本人可见的详情、追问列表和时间线读取，运营从审核队列读取待审项。待审/驳回会记录机器审核事件。人工通过后发布、计数并产生一次通知；驳回不公开、不计数、不通知 HR；下架已发布追问扣减计数，重复审核不能重复发布或计数。撤回待审追问不会扣减公开计数，也不能再通过。前端须明确显示审核结果；即时驳回保留输入供修改，待审提示通过后才会公开。

当前只接受上述新版格式，不再自动猜测目标回答。V12 建立主回答关联；V13 停用仍缺少该关联的记录及其回复，并校正受影响问题的发布数量，原始行保留但不参与页面读取、待办或审核队列。其他开发分支需要同步必填字段后再联调。

### GET `/api/v1/tags/categories`
固定标签目录的大类列表（来自 V5 迁移），匿名可访问。按类目下最高权重倒序返回；"推荐"由前端虚拟插入，不在响应中。
```json
[
  { "name": "求职阶段", "tagCount": 7 },
  { "name": "求职准备", "tagCount": 7 }
]
```

### GET `/api/v1/tags?category=&keyword=&limit=50`
固定目录标签查询，匿名可访问。
- `category` 为空：返回按 `weight` 倒序的推荐标签（前端默认取 12 条）。后续个性化推荐只需改后端该分支，前端无需调整。
- `keyword` 非空：忽略 `category`，按标签名和 slug 全局模糊搜索。
- `limit` 默认 50，服务端裁剪到 1~100。只返回 `category` 非空的目录标签，历史自定义标签不会出现。
```json
[
  { "id": 8, "name": "简历", "slug": "简历", "category": "求职准备" }
]
```
提问时仍按标签名提交（`POST /api/v1/questions` 的 `tags`）；按标签筛选公开列表时使用 `slug`。

## 3. HR 问题池与回答

### HR 原创帖子：第一阶段

原创帖子独立于学生问题和问答回答。HR 可以保存草稿、管理本人帖子和提交待审。公开阅读仅显示已发布帖子。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/hr/posts?status=all&cursor=&limit=5` | 本人 ID 倒序列表，状态 `all|draft|pending_human|rejected|withdrawn|published|removed`，limit 1–50 |
| GET | `/api/v1/hr/posts/{id}` | 本人完整帖子，其他 HR 404 |
| POST | `/api/v1/hr/posts/drafts` | `{clientKey,title,body,tags}`，相同作者/clientKey 不重复建稿 |
| PUT | `/api/v1/hr/posts/{id}/draft` | `{version,title,body,tags}`，仅草稿、驳回和已撤回状态可编辑 |
| POST | `/api/v1/hr/posts/{id}/submit` | `{version}`，必填标题/正文，规则拦截为 rejected，否则统一 pending_human |
| POST | `/api/v1/hr/posts/{id}/withdraw` | `{version}`，待审/已发布改为 withdrawn |
| DELETE | `/api/v1/hr/posts/{id}/draft` | 请求体 `{version}`，仅删除草稿 |

标题最多 200 字、正文 10000 字、最多五个固定目录标签。首份草稿 `clientKey` 为 16–64 位字母/数字/短横线，前端使用 UUID。详情返回 `id/title/body/tags/status/version/createdAt/updatedAt/submittedAt`，列表用 `excerpt` 代替 body，分页 `items/nextCursor`。保存和状态更新递增版本，旧版本返回 409，未经归属校验不能读取或更新。

上述本人管理接口仅 HR 可用，作者取自真实会话。可选请求头 `X-CareerQ-Hr-Id` 只比对发起页面的账号，与当前身份不同返回 40902。V18 增加独立 hr_posts/hr_post_tags。草稿服务器保存，本机保留未同步内容与冲突备份。详见 [HR原创帖子分阶段开发](HR原创帖子-分阶段开发.md)。

### HR 分享公开阅读

| 方法 | 路径 | 说明 |
|---|---|---|

### HR 站内通知

通知从启用后新发生的业务产生：学生指定回答的追问发布、本人回答/追问回复人工审核通过或驳回、运营直接下架或举报下架。普通直接发布、即时拦截及作者撤销不额外通知。读取消息不清除 HR 待回复任务，内部审核备注不作为通知内容公开。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/hr/notifications?category=all&unreadOnly=false&cursor=&limit=5` | `category=all|followup|system`，ID 倒序分页，返回 `items`、`nextCursor`、`snapshotId` |
| GET | `/api/v1/hr/notifications/unread-count` | 返回 `total`、`followup`、`system`、`snapshotId` |
| POST | `/api/v1/hr/notifications/{id}/read` | 幂等标记本人消息已读并返回重新校验后的目标 |
| POST | `/api/v1/hr/notifications/read-all` | `{ "throughId": snapshotId }`，仅标记快照范围内消息，新到消息不受影响 |
| GET | `/api/v1/hr/answers/{id}` | 本人的单条回答/回复安全记录，供审核和下架通知直接定位 |

### HR 个人中心

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/hr/profile` | 当前 HR 职业资料：`id`、`nickname`、`avatarUrl`、`companyDisplay`、`industry`、`position`、`bio`、`specialties`、`verifyStatus` |
| PATCH | `/api/v1/hr/profile` | 更新昵称、企业展示名、行业、职业方向、简介及擅长领域；认证状态和账号角色只读 |
| GET | `/api/v1/hr/stats` | `rootAnswerCount`、`followupReplyCount`、`likeCount`、`usefulCount` |
| GET | `/api/v1/hr/answers?kind=all&status=all&cursor=&limit=5` | 逐条返回本人的主回答/追问回复，按 ID 倒序游标分页；与按问题聚合的工作台接口独立 |

以上仅 HR 可访问，身份只取当前登录会话，不接受请求指定答主。未登录 401、非 HR 403，非法筛选/游标/长度 400。资料 PATCH 的 null/未传字段保留原值，可选字段空字符串或空列表清空；空企业展示名归一为“某行业企业”，昵称不可为空。简介最多 500 字，擅长领域最多 6 项且每项最多 24 字。头像复用既有 `/me/avatar`，不修改学生资料接口。

统计只计算所属问题仍公开已发布、回答本身已发布且关联有效的本人内容；审核中、驳回、撤销和下架均不计入，主回答与追问回复分开统计。

回答筛选 `kind=all|root|reply`；`status=all|published|reviewing|rejected|withdrawn|downlisted|removed`，其中 reviewing 合并机器/人工待审，withdrawn/downlisted 按移除来源区分，removed 包含来源不明的全部移除记录。`cursor` 为正整数，`limit` 为 1–50，默认 5。返回 `items` 与 `nextCursor`，末页游标为空/省略，独立回答不合并。

记录字段为 `id`、`questionId`、`questionTitle`、`canViewQuestion`、`rootAnswerId`、`followupId`、`body`、`status`、`removalSource`、`likeCount`、`usefulCount`、`createdAt`。移除记录正文为空且互动计数归零，原问题不再公开发布时仅返回通用标题和 `canViewQuestion=false`；不通过本人记录接口泄露隐藏问题标题。本人有效记录复用既有撤销接口，成功后刷新列表和统计。

前端独立 `/hr/profile`，HR 旧 `/me` 自动跳转；每页 5 条，切筛选重置页码，空页回第一页，末页禁用下一页。打开详情携带回答 ID 定位，返回保留筛选、页码和滚动位置。V15 增加简介、擅长领域 JSON 和答主记录分页索引。协作与字段约定详见 [HR个人中心-开发说明](HR个人中心-开发说明.md)。

### GET `/api/v1/hr/question-pool?cursor=&limit=`
HR 待回答池，按问题 ID 倒序游标分页。只含已发布公开问题、`answer_count = 0` 且没有已发布或正在审核的回答。任意 HR 提交回答审核后，问题会立即移出待回答池，避免重复回答。

### GET `/api/v1/hr/answered-public-questions?cursor=&limit=`
所有 HR 已回答或正在审核回答的公开问题，按问题 ID 倒序游标分页，不区分回答者。`hasPendingAnswer` 标记是否存在待审核回答；此类问题仍显示为 0 个已发布回答，审核通过后才计入 `answerCount`。

### GET `/api/v1/hr/answered-questions?cursor=&limit=&pendingFollowupsOnly=false&cursorAt=`
当前 HR 提交过主问题回答或追问回复的已发布公开问题。默认按问题 ID 倒序分页，原有数字 `cursor` 用法保留。HR 身份从登录会话读取，不接受客户端传入用户 ID；每个问题只出现一次，并返回该 HR 最近一条回答摘要与状态。`myAnswer.followupId` 为空表示回答主问题，非空表示回复对应追问。审核中、未通过或已下架的本人回答也保留在本人记录中。

- `followups` 只统计关联具体主回答、已发布且发给当前 HR 的学生公开追问，不包含其他 HR 或缺少回答关联的记录。
- `pendingCount`：当前 HR 没有已发布或审核中回复的追问数量；`reviewingCount`：没有已发布回复、但有审核中回复的追问数量。一条追问无论有多少回复都只计数一次。
- `firstPendingFollowupId`：最早一条待回复追问 ID，用于详情定位；`latestPendingAt`：该问题下最新待回复追问时间，没有待办时这两个字段省略。
- 回复通过后消除待办；审核中单独显示；被驳回、撤销或下架后，如果该追问已没有其他已发布或审核中回复，恢复待办。追问撤销或问题不再公开发布后不再计数。仅浏览详情不会消除待办。
- `pendingQuestionCount` 与 `pendingFollowupCount` 是当前 HR 在全部相关问题中的待回复问题数与追问数，不是当前页的合计。
- `pendingFollowupsOnly=true` 时，后端先筛选有待回复追问的问题，再按 `latestPendingAt DESC, questionId DESC` 分页；旧问题收到新追问同样按此排序。第一页不传游标，后续必须同时传上页 `nextCursor` 和 `nextCursorAt`。普通列表不传 `cursorAt`，两种模式的游标不能混用。到末页两个后续游标字段均省略或为 null。
- 前端仍每页五条；刷新列表或从详情返回时重新取数。任务状态实时变化，新增或恢复的任务通过刷新第一页获取。

响应示例：
```json
{
  "items": [{
    "question": { "id": 42, "title": "如何准备面试？", "followupCount": 1 },
    "myAnswer": {
      "id": 108,
      "followupId": null,
      "body": "建议先梳理岗位要求……",
      "lengthType": "detailed",
      "status": "published",
      "createdAt": "2026-11-18T10:00:00"
    },
    "followups": {
      "pendingCount": 1,
      "reviewingCount": 0,
      "firstPendingFollowupId": 201,
      "latestPendingAt": "2026-11-20T18:30:00"
    }
  }],
  "nextCursor": null,
  "pendingQuestionCount": 1,
  "pendingFollowupCount": 1
}
```

### POST `/api/v1/questions/{id}/answers`
回答公开问题的主问题。回答经过内容审核；审核通过后计入问题回答数。HR 不可回答未发布或不符合公开条件的问题。
```json
{ "body": "……", "lengthType": "detailed" }
```
`lengthType`: `one_liner` | `detailed`。

### POST `/api/v1/questions/{id}/followups/{followupId}/answers`
HR 回复指定的、属于该问题且已发布的学生追问。学生不能调用；问题、追问 ID 与目标 HR 必须匹配，跨 HR 线程返回 404。回复沿用回答的内容审核、点赞与标记有用能力。
```json
{ "body": "……", "lengthType": "detailed" }
```

### POST `/api/v1/questions/{id}/withdraw`
提问者撤回自己的问题。仅允许尚无回答记录且状态符合要求的问题；成功返回更新后的问题对象。非作者返回 403，已有回答、重复撤回或状态不允许返回 409。

### POST `/api/v1/answers/{id}/withdraw`
作者撤销自己的 HR 主问题回答或追问回复。成功返回更新后的回答对象；已发布回答撤销时递减公开回答数，审核中回答不影响公开计数。非作者返回 403，重复或非法状态返回 409。

成功返回 `status=removed`、`removalSource=author`。已被运营下架的回答再次撤销返回 409，提示“回答已被运营下架，不能再撤销”；不会改写首次移除来源。

HR 工作台“我回答过的”的本人摘要、问题详情的本人主回答及追问回复均提供常显撤销按钮。操作前确认，处理期间禁用重复点击，成功后刷新内容、发布数量及追问待办；其他用户不显示该入口。

### POST `/api/v1/questions/{id}/followups/{followupId}/withdraw`
学生撤销自己的追问。成功返回更新后的追问对象；已发布追问撤销时递减公开追问数。非作者返回 403，重复或非法状态返回 409。

## 4. 互动与内容

### POST `/api/v1/interactions`
点赞 / 收藏 / 标记有用 / 不喜欢（幂等：重复点击不重复计数）。
```json
{ "targetType": "question", "targetId": 1, "type": "like" }
```
- `targetType`：`question` / `answer`
- `type`：`question`、`answer` 支持 `like` / `useful` / `favorite`
- `dislike`（不感兴趣）只支持 `question`：影响推荐偏好，并让该问题从当前用户的推荐流中消失；不更新任何公开计数

### DELETE `/api/v1/interactions`
取消点赞 / 有用 / 收藏 / 不喜欢（幂等；请求体同 POST）。撤销 `dislike` 后问题可重新出现在推荐流。

### GET `/api/v1/me/favorites?targetType=&cursor=&limit=`
我的收藏列表（按收藏记录 ID 倒序，游标分页）。从会话读取用户，仅查询本人的收藏，先过滤非公开/未发布问题及失效回答，再分页；不会出现整页为空却持续提供后续游标的情况。`targetType=question|answer` 可选，不传返回两类；学生页面每页 5 条。
```json
{ "items": [{ "targetType":"question", "targetId":1, "questionId":1, "followupId":null, "title":"...", "excerpt":"...", "createdAt":"..." }],
  "nextCursor": null }
```

`questionId` 为内容所属问题，`followupId` 仅追问回复有值；回答收藏通过 `targetId` 定位具体回答。取消收藏复用 `DELETE /interactions`，不改变收藏原文；当前页取消后为空则回第一页。学生入口为 `/me?tab=favorites`，从详情返回保留原页。

### 学生站内通知

仅学生使用，收件人取自会话。提供真实 HR 回答/追问回复、收到的赞，以及本人问题/追问的人工审核结果和运营下架通知。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/student/notifications?category=all&unreadOnly=false&cursor=&limit=5` | 分类 `all|reply|like|system`，ID 倒序；返回 `items`、`nextCursor`、`snapshotId` |
| GET | `/api/v1/student/notifications/unread-count` | `total`、`reply`、`like`、`system`、`snapshotId` |
| POST | `/api/v1/student/notifications/{id}/read` | 幂等标记本人的消息已读，并重新判断目标可见性；他人消息返回 404 |
| POST | `/api/v1/student/notifications/read-all` | `{ "throughId": snapshotId }`；快照之后新消息继续未读 |

通知含 `id/type/category/title/message/questionTitle/questionId/answerId/followupId/destination/createdAt/readAt`。`destination=question|unavailable`；回答摘要在读取时从仍可见的正文生成，不保存正文快照或审核内部备注，撤销/下架后不再返回原摘要。审核结果只对内容作者显示，点赞不公开点赞人的身份；本人点赞不通知，同一人取消后再点赞不重复通知。HR 回答通过审核后才通知学生，重复处理由唯一事件键去重，业务与通知同事务。

V17 新建学生通知表，并仅依据迁移时已存在的有效公开回答与非本人点赞补入真实记录，保留原事件时间；不猜测旧审核结果。页面 `/messages` 每页五条，支持分类、未读、单条/快照批量已读、真实顶部红点及详情定位，返回保留筛选、页码和位置。原 HR 通知表、接口及角色边界保持原约定。

### 学生提问草稿（前端本机保存）

标题、正文及标签按学生 ID 自动保存到本机。离开、刷新、退出重登和重开浏览器可恢复本人未完成草稿；没有自动过期删除。发布或提交待审成功后清除，提交失败/即时拒绝保留；主动清空需要确认。存储不可用时明确提示，离开前确认，关闭页面前触发浏览器未保存提示。草稿不上传到公开池，也不属于跨设备草稿服务。

同账号跨标签页冲突时先保留被覆盖版本，提供“其他未完成草稿”恢复入口；未编辑的旧页面不回写，提交/清空仅作用于本页对应版本，不能删除其他页面的新草稿。

### 互动状态（随详情返回）
- `GET /api/v1/questions/{id}` → `data.viewer: { liked, usefuled, favorited, disliked }`；每个回答带 `liked` / `usefuled`
- 问题与回答带对应互动计数；原创职业观点帖为待开发能力，不在本版接口中提供
- 公开问答 feed：问题支持点赞/收藏/举报，卡片「更多」菜单另有「不感兴趣」（`dislike`）；HR 回答支持点赞/举报；FollowUp 只支持「回复」预填 `@昵称`，点赞/举报暂不落库

### POST `/api/v1/reports`
举报问题或回答（`targetType=question|answer`，回答包括 HR 主回答和追问回复）。作者举报自己的内容返回 HTTP 403（业务码 `40300`），举报队列不会新增记录。
```json
{ "targetType": "answer", "targetId": 1, "reason": "spam", "detail": "..." }
```

## 5. 运营后台（RBAC：operator / admin）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/moderation/queue` | 问题、回答、追问的待审队列，返回正文和上下文；回答/追问按需带 `rootAnswerId`、`followupId` 定位所属楼层与追问 |
| POST | `/api/v1/admin/moderation/{targetType}/{id}/decide` | `{ "decision": "approve"\|"reject"\|"remove", "note": "..." }` |
| GET/POST | `/api/v1/admin/moderation/words` | 词库查询 / 新增或更新（仅管理员） |
| GET | `/api/v1/admin/reports?status=pending` | 举报队列 |
| POST | `/api/v1/admin/reports/{id}/handle` | `{ "decision": "dismiss"\|"remove", "note": "..." }` |
| GET | `/api/v1/admin/metrics` | 待审/已发布/举报积压计数 |

运营直接下架回答与举报处理下架共用移除逻辑，并记录人工处理信息。原状态为 `published` 时递减一次 `answerCount`（包括追问回复）；待审或未通过内容不扣减。重复下架或处理同一内容的其他举报不再扣减，也不覆盖首次移除来源、操作者和时间。最后一条有效回答移除后，若没有其他已发布或待审回答，问题可重新进入 HR 待回答列表。已处理举报再次处理仍返回 409。

V14 新增移除来源等内部字段，将旧移除记录标为 `unknown`，按实际已发布 HR 回答/回复总数校正公开问题的 `answerCount`；不改写历史 Flyway 迁移，不猜测旧操作来源，也不增加历史内容展示功能。

- `ThreadItem.kind` 区分 `hr_answer`、`followup_answer`、`followup`，不能把 HR 的追问回复发送到学生追问接口。

## 7. 状态与权限

- 问题和回答使用 `pending_machine` / `pending_human` / `published` / `rejected` / `removed` 等发布状态。
- `scope` 仅为 `public`；未发布内容的读取按作者归属和审核职责判断。
- `Answer.lengthType` 为 `one_liner` / `detailed`。
- 学生可创建问题和追问；HR 可回答主问题与回复指定学生追问；运营可审核和处理举报；管理员可维护词库。
- 原创帖子第一阶段本人创作管理已实现，运营审核和公开互动仍待开发；真实 HR 认证继续暂缓。学生与 HR 站内通知已按本契约分别提供。

## 8. 前后端联调流程（建议）

1. 后端先用 springdoc 生成 OpenAPI（`/v3/api-docs`、`/swagger-ui`），前端据此生成类型与 mock。
2. 前端本地 dev server 代理 `/api` → `http://localhost:8080`，避免 CORS。
3. 契约变更**先改本文件**并在 PR 说明，前后端同步评审，禁止后端单方面改字段。
4. 联调顺序：鉴权 → 公开列表/详情 → 学生提问 → HR 回答及回复追问 → 互动 → 审核与举报。
