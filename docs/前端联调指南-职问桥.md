## 2. 鉴权流程（Cookie 会话 + CSRF）

```text
① POST /api/v1/auth/sms-code   { phone }
② POST /api/v1/auth/login      { phone, code }        → 服务端 Set-Cookie: JSESSIONID
③ GET  /api/v1/auth/csrf                              → { token, headerName: "X-XSRF-TOKEN" }
④ 之后所有非 GET 请求带 Cookie + X-XSRF-TOKEN: <token>
```

要点：

- 前端**不需要保存 token 到 localStorage**，会话由 `HttpOnly` Cookie 承担。
- 跨域开发时 fetch 必须带 `credentials: "include"`；推荐用 Vite 代理避免跨域。
- 登录后必须调一次 `/auth/csrf` 拿 token，否则 POST 会 **403**。
- 登出：`POST /api/v1/auth/logout`（会失效服务端会话）。

### 2.1 Vite 开发代理（推荐）

```ts
// vite.config.ts
export default defineConfig({
  server: {
    proxy: {
      "/api": { target: "http://localhost:8080", changeOrigin: true },
    },
  },
});
```

同域代理下无需处理 CORS。若前端直连 `8080`，后端已允许 `http://localhost:5173`（`careerq.cors.allowed-origins`）。

### 2.2 TypeScript 请求封装示例

```ts
const BASE = "/api"; // 走 Vite 代理

let csrfToken: string | null = null;

async function ensureCsrf(): Promise<string> {
  if (csrfToken) return csrfToken;
  const res = await fetch(`${BASE}/v1/auth/csrf`, { credentials: "include" });
  const body = await res.json();
  csrfToken = body.data.token;
  return csrfToken!;
}

export async function api<T>(
  path: string,
  options: RequestInit = {},
): Promise<T> {
  const method = (options.method ?? "GET").toUpperCase();
  const headers = new Headers(options.headers);
  headers.set("Content-Type", "application/json");
  if (method !== "GET") {
    headers.set("X-XSRF-TOKEN", await ensureCsrf());
  }
  const res = await fetch(`${BASE}/v1${path}`, {
    ...options,
    method,
    headers,
    credentials: "include",
  });
  const body = await res.json();
  if (!res.ok) {
    const error = new Error(body.message ?? `HTTP ${res.status}`);
    (error as any).code = body.code;
    (error as any).status = res.status;
    throw error;
  }
  return body.data as T;
}
```

> 会话失效（401）时清空 `csrfToken` 并跳登录页。

## 3. 常用接口速查

完整定义见 [`openapi.json`](openapi.json)；以下是联调最常用的调用顺序。

| # | 接口 | 说明 |
|---|---|---|
| 1 | `POST /auth/sms-code` → `POST /auth/login` → `GET /auth/csrf` | 登录三步 |
| 2 | `GET /questions?tag=&cursor=&limit=` | 公开问题列表（无需登录） |
| 3 | `POST /questions` | 提问：`{title, body, tags[], scope: "public"\|"private"}` |
| 4 | `GET /questions/{id}` | 详情：`{question, answers[], followups[]}` |
| 5 | `POST /questions/{id}/answers` | HR 回答：`{body, lengthType}` |
| 6 | `POST /questions/{id}/followups` | 追问：`{body}` |
| 7 | `POST /interactions` | `{targetType, targetId, type}` |
| 8 | `GET /hr/private-pool` / `POST /hr/questions/{id}/claim` | HR 私密池 / 认领 |
| 9 | `POST /questions/{id}/close` / `POST /questions/{id}/publish` | 关闭 / 申请脱敏公开 |
| 10 | `POST /reports` | 举报 |
| 11 | `GET /posts` / `GET /feed/highlights` | 已审核公开沉淀 |
| 12 | `GET /admin/moderation/queue` 等 | 运营后台（OPERATOR/ADMIN） |

### 3.1 列表分页

请求 `?cursor=<上一页最后一条 id>&limit=20`，响应：

```json
{ "code": 0, "message": "ok", "data": { "items": [], "nextCursor": 12 } }
```

`nextCursor == null` 表示没有下一页。

### 3.2 问题状态（前端展示用）

| 状态 | 含义 | 前端展示建议 |
|---|---|---|
| `pending_machine` / `pending_human` | 机器/人工审核中 | 「审核中」，不展示内容 |
| `published` | 公开问题已发布 | 正常展示 |
| `rejected` | 未通过审核 | 提示作者修改 |
| `removed` | 已下架 | 显示「内容已下架」 |
| `open` | 私密问题待认领 | 作者可见「等待 HR 认领」 |
| `assigned` | 已认领 | 作者可见「HR 已认领」 |
| `closed` | 已关闭 | 可申请公开 |
| `public_pending` | 申请公开待审核 | 「公开审核中」 |
| `public_archived` | 已沉淀公开 | 展示在公开池 |

## 4. 错误码与排查

统一响应体：`{ "code": 0, "message": "ok", "data": ... }`；失败时 `code != 0`。

| HTTP | code | 含义 | 常见原因 |
|---|---|---|---|
| 400 | 40001 | 参数不合法 | 手机号格式、缺少必填字段 |
| 401 | 40100 | 未登录 / 会话失效 | 未带 Cookie、会话过期 |
| 403 | 40300 | 无权限 | 学生回答、未认领 HR 看私密、CSRF 失败 |
| 404 | 40400 | 资源不存在 | 问题未发布/已删除 |
| 409 | 40900 | 状态冲突 | 重复认领、未关闭就申请公开 |
| 500 | 50000 | 服务异常 | 看后端日志 |

高频问题：

- **POST 一律 403**：没拿 CSRF token，或没带 `X-XSRF-TOKEN` 头。
- **401 但明明登录了**：Vite 代理没转发 Cookie（检查 `changeOrigin` 与 `credentials`）；或前端直连跨域未带 `credentials: "include"`。
- **CORS 报错**：直连 8080 时确认来源是 `http://localhost:5173` 或 `http://127.0.0.1:5173`；其他端口改 `careerq.cors.allowed-origins`。
- **中文乱码**：确认请求 `Content-Type: application/json; charset=utf-8`，body 用 UTF-8 编码。

## 5. 联调顺序建议

1. 登录三步 → `/me` 能拿到用户与角色
2. 公开问题列表 + 详情（匿名可看）
3. 学生提问 → 列表出现（普通内容直接 published）
4. HR 登录 → 回答 → 详情出现回答、计数 +1
5. 点赞/收藏/有用 → 计数变化
6. 私密工单：学生私密提问 → HR 私密池认领 → 回答 → 追问 → 关闭 → 申请公开
7. 运营后台：审核队列 → 审批 → `/posts` 出现；举报 → 处理
8. 联调完成后跑 `scripts/smoke-test.ps1` 做回归
